## 分平台离线测试结果（2026-09-19 补充）

此前各节的“2078 passed”是在类 Unix 开发机上得到的；当时 CI 只在 Linux 上跑全量，Windows 与 macOS 只跑独立安装测试，因此不能代表其他平台。下面是在 **Windows 11（中文系统，默认 GBK 代码页），Python 3.12.10，`.[dev,mcp,mysql]`** 上对同一版本的实测：

| 代码状态 | `PYTHONUTF8=1` | 不启用 UTF-8 模式（默认 GBK） |
|---|---|---|
| `891847e` 原样 | 40 failed / 2048 passed / 12 skipped，约 4 分 40 秒 | 43 failed |
| 本地修复后（见 CHANGELOG“未发布”一节） | **0 failed / 2134 passed / 43 skipped**，约 32 秒 | **0 failed / 2134 passed / 43 skipped** |

修复后连续 6 轮（两种编码交替）结果一致。43 个跳过的理由：27 个属于仅支持 macOS/Linux 的旧 Cursor 工作区工具；其余需要 POSIX 权限位、symlink 创建特权或线上凭证。原 40 个失败中约一半是产品问题而不只是测试问题：Windows 上取消/超时无法中断阻塞读、文件锁首次创建时的竞态、缓存淘汰依赖文件时间戳粒度、归档路径超过 260 字符、bootstrap 写出非法 JSON。

GitHub Actions 的新矩阵在提交 `a5bda72` 上五个任务全部通过：Ubuntu（Python 3.10、3.12）、macOS（3.12）、Windows（3.12，UTF-8 模式）与 Windows（3.12，系统代码页）。首轮 CI 曾在 Windows 运行器上暴露 3 个取消用例的时序假设（用 0.1 秒定时器触发取消，而运行器上仅构建 TLS 上下文就更久），已改为在读取真正阻塞的那一刻触发取消。CI 失败时会把失败用例写入注解，无需登录即可查看。

尚未覆盖：Windows 上属主/ACL 校验仍未实现（体检会如实标出）；本轮没有做任何带凭证的线上调用。

## GitHub 上传前复核

上传前再次运行基础环境全套测试：**2078 passed，23 skipped**；Python 3.12 的独立 wheel/MCP、来源选择与额度回退专项：**60 passed**。发布说明已改为从仓库获取源码，私有技能库存加入 Git 忽略规则；凭证、会话和本地参考原文不上传。上文 ZIP/wheel 散列属于此前导出的交接快照，GitHub 版本以提交号识别。

远端跨系统检查见 [GitHub Actions](https://github.com/Chener6280/ir-search/actions/workflows/standalone.yml)，必须核对实际提交的运行结果。不能由本机通过推断远端通过。

首次远端检查（`59154bf`）发现：Linux 缺少旧 Cursor 模板所需的 zsh；Windows 的 asyncio 内部回环通信被测试的零网络保护误拦；提交前空白清理触发了既有多行格式检查。修复保留了旧模板的明确 zsh 依赖和应用外连阻断；并补入模板输出目录的空 `.gitkeep` 文件，实际输出仍被忽略。修复版本须以其远端检查结果验收。

第二轮（`041f01a`）Linux 两个 Python 版本和 macOS 均已通过；Windows 的安装探针增长后超过了系统命令行长度上限，改为在独立目录运行 UTF-8 探针文件，并在所有 MCP 检查中复用预先创建的事件循环。另排除同步客户端生成的临时上传配置，防止凭证文件的旁文件被误纳入 Git。
