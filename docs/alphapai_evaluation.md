# Alpha派素材源评估

> 后续实施状态：账号版 adapter 已完成，使用方法与最新边界见 [Alpha派指南](alphapai_material_adapter.md) 和 [验收](alphapai_material_acceptance.md)。以下保留接入前的评估记录。

评估日期：2026-09-18。结论：**值得接入 `search_materials` / `retrieve`，优先补充会议纪要、渠道交流与券商观点；当前手机号账号可用，但不能承诺完整逐字稿或全库权限。** 本轮完成参考审查和有限真实取数，尚未注册生产 adapter，也未改变行情数据来源或 `deep_research`。

## 两套参考能力

| 项目 | 华福 `alphapai-research` | `alphapai-transcript` |
|---|---|---|
| 接入 | 官方 Open API，专用 Key 放 `app-agent` 请求头 | 网页账号密码登录，取得会话后调用网页接口 |
| 本轮凭证 | 未发现可用专用 Key；参考配置是占位值 | 读取本地 env 的 `ALPHA_PIE_PHONE`、`ALPHA_PIE_PWD`，登录成功 |
| 素材 | 文档声明支持内外资纪要、研报、点评、公告、社媒、基金报告等分类召回 | 共享会议纪要目录与详情、本人录音转记目录 |
| 检索 | `recall-data` 返回 `id/type/contextInfo/chunks/sentenceIds` | 关键词、股票、日期、机构等列表筛选；当前排序/匹配规则不透明 |
| 内容 | 召回片段；`isCutOff=false` 也不等于整篇文档完整原文 | 摘要、机器转录、个人转记下载地址；权限和完整性需逐篇判断 |
| 当前证据 | 已读接口文档，未真实验证专用 API 权限 | 已真实验证目录、两篇会议详情、个人转记目录 |
| 长期定位 | 若账户有正式权限，优先作为跨电脑服务接入 | 可先补当前账号能力；浏览器登录作为可选依赖，网页接口变化需监测 |

## 实取结果与诊断

测试为有限只读查询，不调用问答/报告生成，不创建转写任务、不上传音频。登录会话仅在临时浏览器内存中使用，未写入 env 或会话文件。手机号、密码、令牌未输出到报告。

| 检查 | 结果 | 解释 |
|---|---|---|
| 账号密码登录 | 成功，后续只读接口有成功响应 | 不是仅以登录页面跳转判断成功 |
| 参考技能原样传日期 | HTTP 200 / 业务码 `500000`，提示系统繁忙 | HTTP 成功不代表业务成功；失败不能报成零条结果 |
| A 股、茅台、9 月 1—18 日 | 完整时间参数返回 `200000`、5 条候选 | 日期须形如 `2026-09-01 00:00:00` / `2026-09-18 23:59:59`；这只是首个小页面，不是全部结果 |
| 市场不限定、无日期 | `marketTypeV2=""` 返回成功 | 本次对照中出错因素是纯日期写法，不能误诊为不支持全部市场 |
| 自然语言问题、无显式日期 | “贵州茅台9月动销数据”返回 5 条，其中有 1、2 月会议 | 问题里的“9月”没有可靠替代服务端日期过滤；也不能依赖返回顺序代表最新 |
| 共享会议详情 | 两篇成功返回，含 AI 摘要和转录字段 | 未触发参考技能提到的每日查看上限；实际日额度和计费仍未知 |
| 本人转记目录 | 返回非空目录，部分记录有逐字稿和 AI 摘要下载地址 | 没有下载私人文档，下载与文档完整性尚未验收 |
| 官方 `recall-data` | 未测试 | 网页手机号密码不能被当成 Open API Key 使用 |

取得的样本包括 9 月 14 日《兴证食饮｜贵州茅台：拨雾开新局，改革见实效》和 9 月 11 日《中泰食品饮料｜茅台渠道经销商交流》。后者的存量 AI 摘要包含 9 月配额、发货、库存、动销等主题，符合用户希望补充的调研素材范围；这只证明发现了相关研究材料，不构成对其中经营数据的独立核实。

经销商会议详情需要特别保留以下限制：

- `aiSummary.content` 去除 HTML 后约 7,239 字符，是供应商 AI 整理的会议摘要。
- `mtSummary.content` 实际是 JSON 字符串，不能按普通 HTML 直接清洗。本次只有 46 个片段，拼接文本共 507 字符；片段带 `role/bg/ed` 等字段。
- 最末 `ed=152244`，结合字段形态推测为毫秒，约 2 分 32 秒；录音长度字段为 2898，若单位为秒则约 48 分钟。时间单位尚待正式说明确认，但 507 字符与供应商声明的 10683 字量已经不支持“全文完整”的结论。
- `hasPermission=false` 与 `freeAccess=true`、嵌套 `sharePermission.hasPermission=true` 同时出现。权限标记有不同作用域，不能用某一个布尔值推断全库权限、整篇全文或无限下载。
- 同标题、同会议时间的条目在不同请求中返回不同的 opaque `id`。其有效期和稳定性未验证，不能直接当永久文档主键或构造公开永久链接。

当前定位为 **可取材、存在完整性限制**。本次没有验证批量历史覆盖、分页上限、长期会话稳定性、额度计费和正式 API 检索质量；无具体价格依据，不估算调用费用。

## 在 ir_search 中的建议

对外保留一个 `alphapai` 素材来源，内部区分官方 API 与网页会话接入，并在结果中披露实际接入方式；本人转记再使用显式私有集合范围。不同接入方式的权限与成本独立配置，不进行隐藏的失败切换。

第一阶段可按现有账号重构共享纪要的有界搜索与详情读取。手机号密码统一从 env 读取；浏览器只承担必要登录，核心查询不依赖桌面技能或开发者路径。若后续直接 HTTP 查询不可用，保留可选浏览器后端及清晰诊断。需要人机验证或登录失效时明确返回状态。

`search_materials` 负责将调用方给定的实体、关键词、发布日期转换为来源请求；先读取少量列表，再按共享预算读取详情。实现日期规范化、时区/日期含义核验、分页和额度停止，不能只把自然语言问题原样塞进 `word` 并认为筛选条件已执行。会议发生时间和平台发布日期分别保存，二者也不自动等于观点讨论的业务期间。

`retrieve` 应分别返回：

1. 列表摘要与元数据：标为片段，只用于发现线索。
2. 供应商已有 AI 摘要：显式声明生成来源，不能标为录音原文。读取存量摘要不会在本地搜索链路中新增 LLM 调用。
3. 机器转录片段：解析 JSON，保留角色与时间字段；单位未确认时保留原始值并提示未知，确认后才转换。明确本次覆盖区间和截断，不把它宣称为经人工核验的逐字稿。
4. 本人转记文档：后续单独验收、显式启用、账号隔离。下载地址可能具有访问能力，禁止把私有或签名下载地址当作公开引用链接。

引用绑定实际返回文本的哈希和字符区间，记录标题、发布机构、会议/发布日期、内容类型及采集时间。缓存键应包含账号、内容版本和文本指纹；供应商临时 ID 与本地缓存标识分开。相同标题日期只作候选匹配，不能单独据此合并不同会议。无稳定可访问 URL 时使用明确的内部来源引用，不编造链接。

券商纪要属于券商/研究观点来源，渠道交流中的数据属于受访者陈述；AI 摘要和机器转录各自带转换标记。只有证据足以确认上市公司原始披露时才升级相应来源层级，不能因为从 Alpha派取得就统一标成一手官方事实。

第二阶段在取得专用 Open API Key 后，验证分类 `recall-data` 的召回质量、片段覆盖、日期和可追溯性，再补充研报、点评、海外业绩会等。图表检索可作为后续素材能力；问答、公司一页纸、选股与研报生成仍交给上层 skill，不纳入确定性搜索核心。行情和标准财务继续保持 Wind/JYDB/FMP 分工。

上线前至少通过：过期认证与权限诊断、业务错误非空处理、每日额度停止、日期边界、分页重复和 ID 变化、摘要/转录区分、JSON 转录与截断测试、引用定位、私有资料隔离，以及安装包脱离源码目录后的 SDK/MCP 验证。
