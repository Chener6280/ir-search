# Fiona MCP 接入及 Wind/JYDB 比较

2026-09-18。本轮完成专用 Bearer 配置、可安装的只读 Fiona 客户端、真实取数和同日对账。**Fiona 适合补充衍生品投研，当前证据不足以整体替换 Wind/JYDB。**

## 配置与工程边界

官方入口为 `https://track.finoview.com.cn/fiona/mcp/`。本轮只启用 `futures_market_data`、`options_market_data` 两个固定数据路由，使用 `Authorization: Bearer <token>`。Token 仅发给 Fiona，不能作为 Finoview 其他 REST API 的 appkey/appsecret，也不复用给任何其他供应商。HTTP 重定向不跟随，HTTPS 验证不关闭。

本地已使用用户填写的 `FIONA_MCP`；公开规范名称为 `FIONA_MCP_TOKEN`，两者兼容且冲突时报错。私有配置：

```dotenv
FIONA_MCP_ENABLED=true
FIONA_MCP_TOKEN=在本地填写专用Token
FIONA_MAX_CALLS_PER_QUERY=20
```

已有 `FIONA_MCP` 时不必再复制一份 Token。文件保持 0600，并受 Git 忽略。跨电脑用 `IR_SEARCH_CREDENTIALS_FILE` 指向每台电脑自己的私有 env。

实现位于 `ir_search.infrastructure.fiona`，`FionaClient.list_tools` 发现工具，`FionaClient.read` 只允许两路由内文档列明的只读数据工具。保留供应商返回字段、截断信息及时间，不把尚未验收的口径包装为统一数据集。状态检查会显示 `integration_stage=provider_client_not_get_data_adapter`：**尚未注册为 `get_data(provider="fiona")`，也没有更改 Wind → JYDB 或 AKShare 的既有默认路线。**

每个客户端最多执行配置的工具调用数；响应最大 4 MiB，受共享超时和操作预算限制。进程内每路由请求至少间隔 1.1 秒，无自动重试。多电脑合计额度仍由调用方控制。原始错误正文不外传，只返回鉴权、权限、网络、限流、格式或预算等稳定错误码。

## 官方文档与实时目录

[服务总览](https://www.finoview.com.cn/guide/mcp/)将期货基础数据暂列为免鉴权、期权列为需要 Token，策略以服务端为准；本轮两个路由均用用户要求的 Bearer 方式成功接入。实时握手版本为 4.0.4，期货目录返回 15 个工具、期权返回 11 个工具。

[期货文档](https://www.finoview.com.cn/guide/mcp/futures_market_data.html)列出日线、分钟线、主力行情、合约交易参数、会员持仓、波动率和仓单。[期权文档](https://www.finoview.com.cn/guide/mcp/options_market_data.html)列出合约、日内/日线行情、风险指标与汇总比率；部分属性工具明确针对 ETF，不能把某个工具的描述推广为所有工具的覆盖。

注意接口版本差异：期货历史行情网页描述超限报错，而实时工具说明写截断并提示。接入统一 adapter 时应以实际响应和 `total/returned/truncated/hint` 为准；不把任一种描述写成永久保证。期权文档同时提示会员排名可能因下游组件未提供而返回 501。本轮未调用会员排名、仓单、研报或 AI 分析路线，不把目录可见当成数据已验收。

主要对账日期为 **2026-09-11**，测试发生于 2026-09-18；这是有限截面，不是全历史认证。

|---|---|---|
| 期货 EOD | IF2609、T2609、RB2610、SC2610、M2701、SR2701/SR701、LC2611，共七个合约、六个场所，均取得日线 | 价格、结算、成交量、持仓 49 项与 Wind 和 JYDB 分别全部一致，其中三项为无成交开高低双方均缺失 |

| 交易参数 | RB2610 返回乘数、最小价位、保证金、手续费、交易时间等 | 本机 Wind 期货属性表此前为空，Fiona 能减少此类取材缺口；未把保证金/费用当作用户实际账户费率 |

| 期权 5 分钟 | 90008034 首次调用失败，稍后同参数复测返回 48 根 | 成交量合计 4,104、成交额合计 2,160,427、末根持仓 3,320，均与其自身日线相符；需保留瞬时失败诊断 |

| 2020 历史期货 | RB2010 在 2020-09-10 至 09-11，Fiona 日线为空、合约目录可确认其存续期，Wind 返回两行 | 本次可访问历史行情有实际缺口，不能用 Fiona 替换全部历史数据 |

## 不能忽略的数据口径差异

**金额不能用同一个倍率处理所有 Fiona 接口。** 七个期货日线的“成交额”乘 10,000 后与当前 Wind 归一化人民币元全部一致；同一 RB 分钟接口的 `total_turnover` 汇总已是约 38.66 亿元，对应日线原值 386,632.5。该关系是样本观察，不能替代供应商的单位承诺。日线推算金额与分钟/JYDB 相差 20 元，LC 日线与 JYDB 差 40 元，仍需保留来源精度区别。

**期权成交量、持仓存在新增冲突。** 三个共同合约的 OHLC 和结算价一致，但数量不能宣称全部一致：

| 2026-09-11 样本字段 | Fiona | Wind | JYDB |
|---|---:|---:|---:|
| 90008034 持仓 | 3,320 | 2,235 | 3,320 |
| RB2610C3000 成交量 | 1,600 | 1,609 | 1,609 |
| RB2610C3000 持仓 | 7,597 | 7,588 | 7,588 |
| RB2610C3000 成交额 | 929,385 | 935,000 | 934,965 |

Fiona 与 JYDB 在深市样本一致，并不能单凭“多数相同”判定 Wind 错；RB 样本也不能仅凭 Wind/JYDB 一致判定 Fiona 错。尚未取得交易所原始日文件或供应商口径解释，本轮不平均、不跨源拼接或覆盖字段。可能的更正、统计或更新时间差异仅是待核实事项。

## 对本项目的建议

1. **近期分钟行情优先做 Fiona adapter**：先落地已实取的期货、ETF 期权，再逐类验收股指/商品期权日内；AKShare 保留备用和诊断用途。目前只有个别日内样本通过，尚未实际切换。
2. **期权风险指标单独建数据集**：保留 `model`、`price_type`、频率、IV 单位、希腊值缩放及来源，不与原始行情混在同一字段里。无法确定的口径应返回 partial。
3. **日终/历史继续 Wind → JYDB**：Fiona 先作为显式可选和对照来源。解决上述数量冲突、老合约覆盖及金额单位，再决定是否按具体数据集调整优先级。
4. **工具权限与数据能力分离**：Fiona 专用 Token 只用于 Fiona；工具目录成功只证明接入，不能自动注册所有服务为已通过的数据集。费用、历史起点、批量下载权益、跨电脑使用许可与 SLA 尚需供应商明确，本轮未核实套餐总成本。

Fiona 对“agent 方便调用、衍生品指标齐全、HTTPS 可部署”的适配性较好；本机 Wind 是用户授权的非 TLS 数据库连接，Fiona 在连接方式上更便于跨电脑使用。但这些工程优势并不证明数据一定更准或一定更便宜。
