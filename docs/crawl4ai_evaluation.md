# Crawl4AI 安装实测与 ir_search 改进建议

这是接入前的评估快照；随后已完成核心接入与修复，当前行为见 [统一网页读取指南](web_reader.md)，新增验收见 [接入验收](web_reader_acceptance.md)。下文测量值与“尚未切换”等表述保留原评估时点的状态。

日期：2026-09-16。结论：**值得作为可选浏览器渲染组件接入，优先服务公司资料目录和动态网页；接入前需要解决正文有效性、引用位置和浏览器运行边界。** 本轮完成独立安装和对照实验，生产 SDK/MCP 的网页读取链路尚未切换。

## 安装与实验范围

- 官方 Python 包 `crawl4ai==0.9.3`，Python 3.12.13，macOS ARM64；依赖一致性检查通过。
- 环境：项目目录下 `.local/crawl4ai-venv`；浏览器：`.local/crawl4ai-browsers`。Chromium 153.0.8010.12 / Playwright build 1243；没有使用日常浏览器配置。
- 原始结果与复测脚本在 `.local/crawl4ai-evaluation/`，依赖版本记录为 `.local/crawl4ai-requirements.lock`。这些都是 Git 忽略的本机实验资产，不是已发布包的依赖。
- 8 个真实公开网页：国家统计局年度公报及目录、NVIDIA 业绩稿及财报目录、Microsoft 业绩稿、Apple IR、新华社新闻、余杭政府图解页面。
- 4 个明确标注的合成页面：静态中文财务材料、延迟加载、点击展开、HTTP 200 访问验证页；另有本机自签名 HTTPS 测试。合成材料不作为投研数据。
- 未读取 `credentials.env`，禁用自动 dotenv 加载，清除实验进程中的模型 Key/代理变量；没有登录、没有模型调用、没有付费搜索接口调用。仅访问公开站点及临时本机测试服务。

来源：[官方仓库](https://github.com/unclecode/crawl4ai)、[PyPI](https://pypi.org/project/crawl4ai/0.9.3/)、[非 LLM 提取](https://docs.crawl4ai.com/extraction/no-llm-strategies/)、[Markdown 生成](https://docs.crawl4ai.com/core/markdown-generation/)。

## 真实网页对照

比较现有 `fetch_public_document` 和 Crawl4AI 浏览器读取。顺序执行，不读缓存；浏览器复用，额外等待 1 秒，关闭图片/媒体/字体下载，不使用 LLM。浏览器的正文、候选字段和链接需要独立检查，**非空文本或 `success=True` 不等于取得目标材料**。

主对照使用移除了证书绕过启动参数的实验包装器。首轮未修改启动参数的结果另存 `initial/`，没有用它冒充严格证书校验的验收结果。

| 页面 | 现有读取器耗时 | 浏览器耗时 | 实际观察 |
|---|---:|---:|---|
| [统计局年度公报](https://www.stats.gov.cn/sj/zxfb/202602/t20260228_1962662.html) | 0.47 秒 | 4.56 秒 | 两者均保留预先选定的数值、单位和注释检查点；无需为这类静态正文强制启动浏览器 |
| [统计局公报目录](https://www.stats.gov.cn/xxgk/sjfb/tjgb2020/) | 0.09 秒 | 3.84 秒 | 两者都有年度与标题信息，浏览器没有证明额外必要性 |
| [NVIDIA 年度业绩稿](https://nvidianews.nvidia.com/news/nvidia-announces-financial-results-for-fourth-quarter-and-fiscal-2026) | 1.94 秒 | 4.40 秒 | 两者均保留选定的财务检查点；Markdown 更长不代表取得更多事实 |
| [NVIDIA 财报目录](https://investor.nvidia.com/financial-info/financial-reports/default.aspx) | 1.71 秒 | 3.76 秒 | 初始 HTML 有 0 个 PDF 链接；渲染后有 75 个链接节点，去重后 **65 个不同 PDF 地址**，包含纪要、CFO 说明和年报等链接。仅发现链接，本轮未下载这 65 份文件 |
| [Microsoft 业绩稿](https://www.microsoft.com/en-us/investor/earnings/fy-2026-q4/press-release-webcast) | 9.96 秒 | 4.67 秒 | 两者均有正文；Crawl4AI 输出 10 个结构化表格对象，尚未逐单元格核验。该次 HTTP 较慢，不据单次结果推断浏览器普遍更快 |
| [Apple IR](https://investor.apple.com/investor-relations/) | 1.54 秒 | 3.63 秒 | 主对照仍是加载占位符；额外文字包含导航与版权年份，不算财报读取成功。后续定点复测见下文 |
| [新华社产业新闻](https://www.news.cn/20260714/d9bbf838964d4598ad21b691d2dc5559/c.html) | 0.22 秒 | 1.61 秒 | 两者都有新闻文字，浏览器带来更多页面附属内容，不能据字符数认定质量更高 |
| [余杭政府图解](https://www.yuhang.gov.cn/col/col1229188665/art/2026/art_9b7b5319a74c4c77829b2af66e2e6582.html) | 0.29 秒 | 12.14 秒 | 现有读取器只有标题、日期等，主要材料为图片；Crawl4AI 返回约 441 字符的自身提取错误提示，但仍声明成功。两者均不算完成图解原文读取 |

8 个页面两种工具都返回了非空文本，Crawl4AI 都声明 `success=True`；其中 Apple 和余杭必须判为未取得目标内容。因此不提供虚假的“8/8 正文成功率”。其余页面也只核验了选择的检查点，并非逐字完整性审计。

同一轮耗时中位数：**HTTP 1.00 秒、浏览器 4.12 秒**。这是小样本、特定网络、串行测试结果，包含不同的页面加载工作，不能外推全网成功率或普遍倍数。

### Apple 复测：区分用户私有认证与站点公开前端参数

主对照的四个 Apple 同源只读资料请求带有 `apiKey` 参数，被实验中复用的项目 URL 规则阻止。这里没有使用用户的任何 Key。单纯增加等待时间后仍无 PDF，且 Crawl4AI 仍能声明成功。

在**独立实验**中，仅允许 Apple 官方域名上观察到的四个固定 `/feed/…/Get…` 路径使用该网站前端自身提供的参数，保持 HTTPS/公网检查、不输出参数值，并等待页面出现 PDF 链接。结果：约 **4.61 秒**取得 **32 个不同 PDF 链接**，加载占位符消失。

这证明浏览器能力有用，也说明现有“公开引用 URL 不得包含凭证字段”的规则不能原样套给所有页面子请求。未来需要区分：①返回给调用者的公开出处；②网站自身的同源资源请求；③用户私有供应商认证。不能因此全局放开所有 `apiKey` URL。本轮没有修改生产网络规则。

## 对接时必须处理的发现

### 1. 引用偏移：现有分块逻辑需要先修

把 NVIDIA 业绩稿的 Crawl4AI Markdown 截到与接口一致的 50,000 字符上限，再交给现有 `extract_evidence`：10 条返回引用中，**3 条与其字符区间不一致**。

定位到 `ir_search/evidence/extractor.py` 的 `_split_long_chunk`：分段调用 `strip()` 去掉前导空白后，仍使用去空白前的起点，导致引用偏移。相同实测中的原有 HTML 提取文本没有触发这 3 条问题；它不是对所有既有引用结果的否定，但说明不能直接把 Markdown 塞进 `retrieve`。`search_materials` 的版本引用另有生成逻辑，也需要单独验收。

建议：切块按原文区间计算，修剪空白时同步修正 start/end；增加中文、长英文段落、Markdown 列表/表格、多个相同片段的回归样本。返回前验证 `span.text == text[start:end]`，并绑定具体文本版本哈希。

### 2. 自动过滤可能删掉最有价值的资料目录

对同一次抓取内容离线应用 `PruningContentFilter(threshold=0.48)`：NVIDIA 财报目录由约 31,761 字符变成 **1 个字符**；Apple 未加载完整的目录也几乎被清空。这是本次明确配置下的结果，不代表所有过滤配置都会如此。

建议：原始渲染 HTML 和未过滤文本作为引用依据；过滤内容只能作为检索辅助。目录页按链接条目提取，文章页按正文区域提取，不能使用同一套“正文精简”阈值。日期、单位、否定表述、脚注和小段限定条件应做保留检查。

### 3. 浏览器成功与正文成功必须分开

受控 HTTP 200 验证页被返回 `success=True`；真实余杭页面把库生成的错误说明作为 Markdown 返回；Apple 在资料仍加载时也能成功返回。即使引用字符位置正确，引用到错误页或工具提示仍是错误结果。

建议增加独立内容状态，例如 `article_text / directory_links / loading / challenge / image_only / extractor_error`。只有取得相应目标内容，才能升级到 `extracted_text`；其他情形保留已有摘要/元数据并返回具体诊断。非空长度、HTTP 200、等待函数返回均不能单独作为判据。

### 4. 证书参数不能只看配置值

已安装 0.9.3 的 `BrowserConfig` 默认 `ignore_https_errors=True`。实验显式设为 False 后，检查安装代码又发现 `BrowserManager._build_browser_args` 仍带 `--ignore-certificate-errors` 系列参数。

本机临时自签名 HTTPS 测试证实：

| 配置 | 实际结果 |
|---|---|
| 仅设 `ignore_https_errors=False` | 页面仍成功读取 |
| 实验包装器移除证书绕过参数 | 正确拒绝，返回证书错误 |

包装器同时移除 `--no-sandbox` 并启用 Chromium sandbox，再重跑真实网页。实验未修改系统证书信任；临时证书及私钥已删除。此处是本机固定版本的实测，不能把一个配置开关等同于完整生产安全保证。

建议：固定经验证的版本，使用可审计的启动方式，回归验证自签名/过期证书拒绝、重定向与子资源规则。实验里的方法覆盖属于验证手段，生产实现应使用明确的包装层或经验证的上游修复，不散布临时修改。

### 5. 页面元数据和表格仍要由 ir_search 校验

统计局公报已有 `PubDate=2026/02/28 09:30`，目前通用日期解析没有识别，返回未知；Crawl4AI 返回的元数据也没有自动解决这些日期字段。它不能替代统一的日期口径。

此外，统计局渲染 DOM 有 34 个 `<table>` 元素，但默认策略没有返回结构化表格对象；Microsoft 则返回 10 个。DOM 表格可能含排版表，不能把这当作确定的召回率，也不能假定表格对象的单位/合并单元格已经正确。

建议：解析可信位置的日期和来源字段，保留原始值、解析规则及冲突诊断；结构化表格先保留 caption/header/footnote，不自动变成 `get_data` 的标准数值数据。图解页面另走明确的图片/OCR能力，不把页面文字当作完整图解内容。

## 受控功能测试

静态、延迟加载、点击展开三个合成样本各设 8 个检查点，包括数值、负号、单位、日期、未经审计说明和业务范围限定：

| 合成场景 | 初始 HTML 的现有解析器 | Crawl4AI |
|---|---:|---:|
| 静态页面 | 8/8 | 8/8 |
| 延迟加载正文 | 0/8 | 8/8 |
| 点击后展开正文 | 0/8 | 8/8，使用测试页的固定点击规则 |

这些是已知答案的本机功能测试，不是三篇真实研报。现有解析器使用同一初始 HTML 直接测试，未放开生产组件对本机地址的限制。未测试自动理解任意网页按钮、验证码绕过、登录或付费内容读取。

## 成本与部署影响

- 主对照采样的测试进程及浏览器子进程 RSS 加总峰值约 **931.5 MiB**；这是 RSS 加总，可能包含共享页，不等同于独占物理内存。
- 初次导入/浏览器启动分别约 8.62/2.91 秒；后续已有系统缓存时分别约 0.23/0.25 秒。两种状态不能混成统一冷启动数据。
- 独立 Python 环境约 663 MiB，浏览器约 557 MiB；包含测试所需依赖。约 707 MiB 的临时安装下载缓存已清理，环境、浏览器和实验记录保留。
- 本轮 8 页浏览器观测到多次子请求，远多于每页一次 HTTP；未来的预算应覆盖子请求、总耗时、下载量、进程内存及并发，不能只数顶层 URL。
- 当前项目仍支持 Python 3.9；Crawl4AI 当前包要求 Python 3.10+。应放在可选 extra 或独立受控 worker，保留未安装浏览器时的可用能力与清楚诊断。

## 建议实施顺序

| 优先级 | 改造 | 验收条件 |
|---|---|---|
| P0 | 修复长文本引用位置，增加正文有效性状态 | 长 Markdown/中文/表格引用逐字符一致；错误提示、验证页、加载占位符不得标为正文 |
| P0 | 确定浏览器启动与网络边界 | 证书错误被拒绝；所有子请求受策略控制；公开前端参数不与用户密钥混用；超时能结束浏览器任务 |
| P1 | 统一 `search_materials` 和 `retrieve` 的网页读取层 | 二者调用同一读取策略，共享 Document、出处、日期、预算、错误码；不改变已有 skills 的入口 |
| P1 | 增加可选 `http → browser` 路线 | 静态正文优先现有 HTTP；明确动态/加载缺口或指定站点才渲染；缺依赖返回诊断。权限/TLS/策略拒绝不得靠换后端绕过 |
| P1 | 将浏览器渲染与内容提取分开 | 保存 HTML/文本版本；同一内容可换提取策略；库自身的错误文本不得进入素材库；原始与过滤文本分开 |
| P1 | 补日期元数据与目录链接映射 | 区分发布日期/抓取时间；已发现链接可显式交给 `retrieve`，发现不等于已读全文 |
| P2 | 有限站内发现与增量更新 | 显式域名、深度、页数、并发预算；优先公司 IR、监管和政府网站，不宣布全站穷尽 |

仍保持：国内博查/海外 AnySearch 负责检索发现；Crawl4AI 是读取后端，原网站才是出处。同一网页经多个工具读取不计作独立证据。IMA、星球、公众号的官方/供应商接口继续保留自己的权限和语义；`deep_research` 不扩建。

## 验证边界

现有项目回归测试：`python3 -m pytest -q`，**1168 passed、12 skipped**；另有 5 条 PyMuPDF/SWIG 弃用警告。依赖一致性及变更空白检查通过。这验证了本轮文档和独立实验未影响现有测试，不代表尚未接入的浏览器后端已通过 SDK/MCP 验收。

本轮是小样本评估，不是生产集成验收；实验 HTTP/浏览器网络边界并不完全相同。浏览器实验检查了域名、公网解析及部分路径，但未实现生产级 DNS 固定出口、流量硬上限或跨操作系统验证。图片下载关闭，不涉及 OCR；未做 PDF 附件内容验收；表格未逐单元格核验。

这些差异、失败和过滤损失都保留在结果中。建议实施 P0 后，再对同一组样本进行 SDK/MCP、独立安装包及实际投研 skill 的端到端验收。
