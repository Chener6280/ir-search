# Tushare 正式素材 adapter 验收

2026-09-15，使用本机私有凭证，经正式 `search_materials` SDK 和真实 FastMCP 工具调用验证。此页记录正式 adapter 的结果；先前连接探针见[历史小样本记录](tushare_mcp_acceptance.md)。完整订阅材料留在 Git 忽略的私有 `.local` 目录，不进入文档、测试夹具或发布包。

每类请求候选预算为 5、正文读取预算为 3、单条上限为 6000 字符。引用逐项验证 `span.text == version[source_part][start_char:end_char]` 及版本标识一致性；SDK 三类共核对 28 处，MCP 另外核对 6 处。本次引用均来自实际取得的摘要或正文；协议也支持标题引用，通过 `source_part` 和 `text_scope` 明确区分。

新闻检查了 5 条，其中仅前 3 条按预算解析正文；最终 3 条命中，不应称为检索了全部 629 条。政策两条是同一文号、不同网站及不同文本的发布版本，当前保留为两个组，独立性未建立，不是两项独立政策或两份独立佐证。

三个 SDK 结果和 MCP 结果均为 `partial`，没有把有限检索标成全部完成；来源、文本层级、业务期间未知及原件未验证说明均保留。研报通过的是摘要，不是 PDF 全文；HTML 正文通过的是本地提取和引用定位，未证明与官方原件完全一致。

## 验收发现并修复的问题

新闻整日响应超过原先 4 MiB 限制，且实测 629 行超过上游文档标注的 400 行。修复后响应硬上限为 16 MiB、1000 行；文档行数变为显式覆盖提示，超出时记录 `corpus_documented_row_limit_exceeded`。这两类本地检查失败保留在私有验收记录中，未计入通过样本。

新增合成回归样本覆盖 401/629/1000 行可用、1001 行拒绝、响应字节超限，以及“上游收到”与“实际检查/返回正文”分别计数。测试不复制真实新闻或政策内容。

本轮开发与正式验收共完成 8 次只读业务工具调用及其初始化/通知，共 24 次协议 HTTP 请求；另一次本地诊断在连接构造阶段失败，未发出请求。该统计不是供应商计费或账户余额记录。没有调用目录中的保存、删除或数值工具。
