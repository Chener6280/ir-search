# 公众号省钱读取验收

日期：2026-09-16。实现在 `ir_search` 包内，供 SDK 与 MCP 的 `search_materials`、`retrieve` 使用；桌面 skills 未修改，旧 `deep_research` 未扩建。

## 本次真实结果

以此前已验收的一篇公开公众号文章和一个已配置公众号为样本，受控调用，不批量下载。统计来自实际传输层调用次数，不用响应示例单价推算账户扣费。

| 检查 | 结果 |
|---|---|
| 首次正文读取 | HTTP 未取得合格正文，Crawl4AI 返回 `browser_robots_denied`，转极致了正文接口 1 次 |
| 取得正文 | 17,801 字符；4 个引用片段全部与返回原文字符位置一致 |
| 第二次读取同一文章 | 命中本地缓存；正文供应商调用 0 次；约 0.006 秒（首次约 6.117 秒，仅作本机样本记录） |
| 缓存来源与时间 | 保留 `text_provider=dajiala` 和第一次抓取时间；明确 `cached_snapshot_not_revalidated` |
| 文本一致性 | 两次返回文本 SHA-256 相同，引用位置均正确 |
| 首次公众号列表 | 1 次 `post_history`，返回 12 条记录 |
| 新客户端重复查询列表 | 缓存命中，新增供应商请求 0 次，保留原抓取时间 |
| 浏览器单独检查 | 同一文章返回 `browser_robots_denied`，约 1.72 秒；未绕过站点规则 |

这证明重复读取可以减少供应商请求；没有证明 Crawl4AI 已在微信免费读通。此次可直接观察到的节省来自正文与历史列表缓存。未展示 Key、供应商余额或私有公众号清单，也没有宣称某个实际扣费金额。

## 行为与边界

- 正文成功快照默认有效 24 小时；公众号名称精确匹配 ID 有效 7 天；历史首页有效 5 分钟。
- 后续页缓存有效 24 小时，并绑定完整首页快照。首页或游标变化使旧后续页失效，避免以旧偏移续翻新列表；首页不变时复用有效旧页。列表历史修改仍可能在缓存期内滞后，强制刷新用于最新状态核对。
- `wechat_cache_mode=use/refresh/off` 可选择复用、强制刷新或关闭持久缓存。刷新失败有诊断，不将旧正文当作刷新结果。
- 同一缓存目录用进程间锁串行协调默认读取。四个并发请求的模拟验收只触发一次正文供应商调用，其余三个复用成功结果；锁等待可取消、可超时。
- 原文按最大支持长度缓存，再按调用者要求返回，避免先读短文、再要长文时重复付费；上限截断仍明确标记。
- 浏览器继续遵守站点规则、无凭证环境、隔离运行和请求预算。缺依赖、超时或站点拒绝等情况有可见诊断，保留供应商读取预算；不自动付费重试。
- 正文仍按相关性与 `text_reads_per_source` 预算读取；未读正文可能漏掉正文专有关键词，不把有限检索宣称为账号全量覆盖。
- `complete=false`、发布日期缺失、发布者身份未独立核验、图片音视频未转写等边界保留。

- 基础环境完整测试：`python3 -m pytest -q`，1,275 通过、12 跳过；5 条已有 PyMuPDF/SWIG 弃用警告。
- Python 3.12 的公众号、浏览器、SDK/MCP 与独立 wheel 相关检查：99 通过。
- 覆盖缓存过期、强制刷新、关闭缓存、截断、跟踪参数去重、并发去重、ID 持久化、首页变化失效、缓存损坏、权限、引用、取消和浏览器失败降级。
- wheel 从临时目录构建，检查包内必需模块、资源与私有文件排除，并用本机实际凭证值检查是否误入产物，未发现泄漏。
- 安装到独立 Python 3.12 环境，从无关目录、隔离 Python 模式运行；禁用网络后，SDK 与实际 MCP 工具均读取同一本机缓存成功，得到 17,801 字符且引用正确。两个 MCP 工具均暴露缓存模式参数。
- 这是独立安装和无源码路径验收，不是另一台物理电脑的实测。新电脑使用自己的配置、凭证和缓存；Crawl4AI 仍为可选依赖。
