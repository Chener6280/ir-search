## 修复与边界

- 底层固定公网地址连接复用 `HTTPConnection` 时，TLS 连接仍沿用端口 80 的默认值，导致 HTTPS `Host` 自动附带 `:443`。对同一 Bilibili 详情请求、同一旧 Cookie，只修正默认端口后即从 HTTP 412 变成 200/API code 0。正式修复依照传输协议设置默认端口，保留 TLS 证书、原域名 SNI、公网地址、预算和重定向校验。
- 旧 Bilibili 会话在 `/x/web-interface/nav` 返回未登录。刷新用户已授权的本机 Safari 会话后，该接口返回已登录；刷新只是验收前的本机维护，不是库在运行时自动提取浏览器 Cookie。
- Bilibili 将需要登录、没有字幕、语言不匹配、有字幕条目但下载地址为空分别诊断。请求返回不同视频/分 P 标识时拒绝使用；不存在的分 P 不冒充第一段。API 验证、认证、限流、资源缺失和结构异常分别映射，错误正文不透传。
- 字幕时间显著超出所选分段时长时，不返回正文引用。字幕明显早于视频末尾结束时保留提示及观测字段；不承诺全部语音都有字幕。部分实测响应存在空地址、短字幕或时间不一致，不能据单次成功保证每次都能取得完整文稿。
- 雪球解析避免因真实帖子或登录组件包含“请输入验证码”等字样而误判整页；没有主帖的验证页仍明确失败。遇到来源级验证、认证、限流等停止条件后，平台搜索停止后续正文尝试，保留已发现的摘要及失败原因。
