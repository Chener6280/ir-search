# deep_research 复用审查与维护边界

2026-09-15。目标是提高 `ir_search` 的健壮性、通用性和跨电脑调用能力。根据现有代码逐项检查，仅复用有明确收益的能力。

结论：`deep_research` 保留为兼容入口，暂停功能扩建。新 skills 使用 `get_data`、`search_materials` 和 `retrieve`；研究步骤、口径和结论由调用方负责。本次没有修改 adapters、连接配置或凭证，也没有发起生产数据源请求。

## 已纳入的能力

将 `research/orchestrator.py` 中 `build_actual_evidence_by_source` 的“实际取得证据分层统计”能力，按新素材契约重写到 `services/material_search.py`，作为每个来源的 `returned_evidence`。没有直接搬入依赖旧 `SearchResult`、`Document`、`ClaimVerification` 的整套函数，也没有让核心服务依赖旧研究编排。

原接口的扫描数和命中数不能单独反映阅读程度。例如扫描 20 条、命中 10 条，最终只返回 5 条，其中可能 1 条是截断正文、1 条是摘要、3 条只有标题。新增汇总分别记录这些层级，以及引用来自标题、摘要还是已提取文本，调用方无需把来源命中数误当成已读正文数。

统计仅针对归组及结果限额后返回的版本；同一文档的不同来源记录保留，不增加“独立证据”或“事实可信度”分数。每条记录原有来源、类型、日期、警告和引用位置继续保留。数据结构说明见[素材搜索指南](material_search.md)。

## 审查结果

| 能力 | 决定 | 原因 |
|---|---|---|
| 实际取材与引用的分层统计 | 纳入新素材服务 | 让有限扫描、标题/摘要、正文及引用的差别在来源汇总中可见；没有新增网络请求或依赖 |
| 文档获取、HTML/PDF 提取、URL 安全检查 | 沿用现有共享模块 | 已位于 `documents/`，`retrieve` 已复用；无需再迁移或建立包装层 |
| 证据提取、来源分级和证据类型 | 沿用现有共享模块及契约 | 已位于 `evidence/`、`models.py` 和 `contracts/`；不因暂停旧编排而删除 |
| 期限、取消、调用预算和错误诊断 | 沿用新框架实现 | `RequestContext` 与类型化诊断已有对应职责，重引入旧流程预算会形成重复维护 |
| 官方来源优先和缺口提示 | 保留原则，不迁入固定查询流程 | 新接口已保留来源等级、供应商身份和覆盖缺口；旧流程对公司、行业和具体网站的推断不宜强加给所有 skills |
| 新鲜度判断 | 不迁入旧固定规则 | 旧流程含固定年份关键字和 30/90 天规则；新素材入口显式区分发布日期与业务期间，更适合不同研究任务 |
| 去重 | 保留新素材实现 | 旧报告去重的 URL 归一化会移除查询参数，不适合作为所有材料的文档身份；新素材保留 URL 参数与版本信息 |
| 启发式支持/反驳标签和置信度 | 保留旧独立工具兼容，不接入新素材判定 | 词语重合、方向词和来源等级不足以确认经营事实；不同网站的转载也不足以证明来源独立 |
| 行业专用查询、研究步骤、结论模板与报告骨架 | 留在兼容入口，暂停扩建 | 与具体研究方法绑定；应由使用它的 skill 决定是否需要 |
| 缓存、研究记录存储 | 保留已有组件，不强制接入 | 自动保存私人语料、统一索引和保留策略是独立需求，本次没有必要引入新的存储行为 |

“沿用”指已有公共能力继续供项目使用，不宣称本次新增了这些功能，也不表示旧模块所有启发式行为已经通过全面质量认证。

## 兼容维护措施

- 保留 Python `ir_search.research.deep_research`、CLI `python -m ir_search.deep_research` 和 MCP `deep_research` 的既有名称、参数和结果结构。
- 更新真实 MCP 工具说明、服务器调用指引、README、项目拓扑和 AGENTS.md：新调用方优先组合核心接口，旧研究入口为 compatibility-only。
- 允许维护旧入口的缺陷、安全和依赖兼容问题；未经重新明确需求，不扩充研究模板、不接入新 adapters、不自动串联新数值或素材服务。
- 核心服务不导入 `ir_search.research`。SDK/MCP 和安装包验证检查这一边界。
- 保留旧工作流回归测试，避免“暂停扩建”演变为静默删除或破坏既有调用。

## 验证范围

验证覆盖元数据/摘要/文本及引用分层、文本截断、未知日期、重复来源记录、结果限额后计数、来源失败时保留其他证据，以及 MCP 工具兼容说明。旧工作流继续做回归验证；独立安装验证在无源码目录和禁网络环境中检查 SDK/MCP 与核心服务不依赖旧编排。

验证结果：全项目 `python3 -m pytest -q` 为 **871 passed, 8 skipped**；带可选 MCP/打包依赖的 Python 3.12 环境中，素材服务、框架 MCP、旧研究入口、工具指引及独立安装专项检查为 **71 passed**。独立安装测试构建 wheel 后删除临时源码，从无关目录调用 SDK/MCP，确认资源可用且未携带测试凭证。可发布文件的本机凭证字面值扫描为 0 命中；私有 env 仍被 Git 忽略并保持 0600 权限。
