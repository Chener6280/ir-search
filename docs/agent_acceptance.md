# 交接候选的 Agent 与跨电脑验收

面向 0.2.0rc1 新入口，不使用旧 `deep_research` 作为替代。真实调用可能消耗所选账户额度；**只执行用户选定且本机已配置的来源**，不要为完成表格自动逐个扫所有平台、提取浏览器 Cookie 或登录新账户。已有选择和授权可沿用。

## 通过条件

离线测试/配置检查、登录、搜索发现、读取正文、引用定位分别记录。HTTP 200、登录成功、非空摘要都不能直接判作正文通过。`partial` 可符合预期，但必须说明为何部分；日期、单位或正文不明时保持未知。

SDK 与实际 Agent/MCP 各跑一次关键路径。直接调用 FastMCP 的离线单元测试不等于真实宿主接入验收。保存包版本、文件散列、OS/Python/依赖版本及执行时间；报告模板见[这里](test_report_template.md)。

## 阶段 C：引用、部分失败和宿主回退

- 每篇正文至少核对 3 条引用：`text[start_char:end_char]` 与引用逐字符一致，绑定该文本版本/哈希。摘要引用不算原文引用；无发布日期不能按问题填入。
- 选两个已授权来源，其中一个明确不可用时，保留另一个成功结果和原失败；不要人工删去诊断。
- 配额测试使用 `tests/test_web_quota_fallback.py` 的受控错误，不刻意耗光额度。MCP 返回 fallback_requests 后，由 Agent 真正调用自带 Web Search 一次，保留范围和 max_text_reads，再把公开 URL 交给 retrieve；区分模拟失败与真实搜索/读取。无联网工具时写“待接续”，不是成功。
- 取消/超时后再做一条正常请求，检查服务恢复；浏览器和音频请求不要留下失控进程。会话到期记录恢复步骤，不自动修改账号或绕过验证。

## 阶段 D：结果交接

用[报告模板](test_report_template.md)分别填写通过、部分通过、失败、未测试，附脱敏诊断、真实来源、扫描/命中/读取数及引用核查；不要提交凭证、私有清单和原文。预算不足或外部阻断可保留缺口。

长期观察、费用聚合、多系统远端 CI 和新来源扩展属于后续工作；本轮不要求另一 Agent 自动实施这些改造。
